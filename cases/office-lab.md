# Office Lab：把协作过程留在可检查的地方

![Office Lab 0.6.0 看板，展示虚构任务](../assets/office-lab-demo.png)

开发、测试、发布之间有很多交接。如果状态只留在聊天里，就很难分清“已经写完”“等待人工预验”和“真正通过测试”。Office Lab 用文件保存任务档案，把条目状态、待确认问题与下一步交接放回同一个看板。

这个项目的重点是协作过程的可见性。不同角色可以有各自的会话，需求按条目推进；尚未明确的业务问题、缺少测试条件的阻塞，也有对应的位置。AI 可以参与执行，最终验收仍有明确的人类入口。

## 实现与取舍

- Node 服务解析 Markdown 档案中的 frontmatter 与需求登记表，再向页面提供结构化任务数据。文件既能被版本管理，也能直接阅读。
- 页面同时显示版本状态与根据条目推导的进度，避免把一个大版本简单压成一个“完成”标记。
- 服务端通过适配器接入 Claude Code 和 Codex，向看板提供统一的消息流。任务档案和人工审批由工作台管理。

## 0.12.0：换一个 Agent 继续做

任务中断后，可以先查看进度摘要、补一条说明，再切换执行引擎。工作台会保留原任务和对话记录，等旧执行停止后，用摘要和近期记录开启新会话。旧引擎无需在线生成交接说明。

## 演示与验证

- **上图为 0.6.0（2026-09-28）**：本地服务加载了 2 份虚构任务档案、共 9 个需求条目。核对了接口和看板显示；演示关闭了 Agent 执行，图中的测试状态是示例数据。
- **0.12.0**：隔离环境验证了两种引擎的会话恢复，以及切换后由新会话继续执行只读任务。完整业务发布流程不在这次验证范围内。

业务文件、真实会话与公司配置没有进入演示。完整仓库暂保持私有。
