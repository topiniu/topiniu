# Office Lab：把协作过程留在可检查的地方

![Office Lab 真实界面，展示虚构任务](../assets/office-lab-demo.png)

开发、测试、发布之间有很多交接。如果状态只留在聊天里，就很难分清“已经写完”“等待人工预验”和“真正通过测试”。Office Lab 用文件保存任务档案，把条目状态、待确认问题与下一步交接放回同一个看板。

这个项目的重点是协作过程的可见性。不同角色可以有各自的会话，需求按条目推进；尚未明确的业务问题、缺少测试条件的阻塞，也有对应的位置。AI 可以参与执行，最终验收仍有明确的人类入口。

## 实现与取舍

- Node 服务解析 Markdown 档案中的 frontmatter 与需求登记表，再向页面提供结构化任务数据。文件既能被版本管理，也能直接阅读。
- 页面同时显示版本状态与根据条目推导的进度，避免把一个大版本简单压成一个“完成”标记。
- Agent SDK 接入独立会话，服务端负责消息流、任务交接、权限审批和中断恢复。此次公开演示关闭了 Agent 执行，因此不把静态任务状态当成自动执行结果。

## 这次实际验证了什么

2026-09-28，以本地仓库中 app 0.6.0 运行真实服务与页面，载入 2 份虚构任务档案、9 个需求条目。接口与界面显示一致；演示实例绑定本机，派工 POST 请求返回 403。截图中的 QA通过等状态是明确标注的演示数据。

历史工作截图中存在更晚版本的界面。本案例截图来自本次运行版本，不拼接成同一次交付，也不宣称已验证完整的自动编排链路。

业务文件、真实会话与公司配置没有进入演示。完整仓库暂保持私有。
